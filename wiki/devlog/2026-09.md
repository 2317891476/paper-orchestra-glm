## 2026-09-11 — Hard wall-clock deadline + thinking-mode off for compression calls
- **Changed**: `methods/agents/content_refinement_agent.py`:
  - `_llm_call_with_deadline(prompt, timeout_sec)` — runs the text LLM call on a
    daemon thread with `join(timeout)`; on expiry raises `TimeoutError` and the
    hung socket is abandoned (daemon ⇒ never blocks process exit). Section-wise
    calls get 300s, whole-document compression 600s.
  - All compression calls now pass `extra_body: {thinking: {type: disabled}}` —
    **root cause of the wedges**: glm-5.3's thinking mode deadlocks server-side
    on section-compression prompts (28+ min, zero bytes, no error). Same prompt
    with thinking disabled returns in 10.3 s (A/B probed 2026-09-11).
  - `_split_latex_paragraphs` + `_compress_by_deletion` — sections > 15KB skip
    the rewrite path entirely: paragraphs are indexed (blank-line split that
    never cuts inside a `\begin/\end` environment; heading pieces and any piece
    **defining** a `\label` are protected), the LLM replies
    `{"delete": [indices]}`, deletions apply mechanically, one follow-up round
    if still over target. Non-thinking glm-5.3 rewrites a 39KB section to 99.7%
    (useless) but ranks paragraph deletions fine: Approach 38986 → 22225 chars
    (57%), all 17 labels intact, 4.2 s (A/B tested 2026-09-11).
  - `_compress_sectionwise`: a failed/timed-out section now **keeps its original
    text and the sweep continues** (was: abort the whole sweep); no checkpoint is
    written so a later sweep retries it. Prompt now states a HARD char ceiling
    ("at most N characters — count them") because the non-thinking model treated
    "roughly 60%" as optional (probe returned 96% of original); accepted sections
    must also shrink below 95% of original or the checkpoint isn't written.
- **Why**: GLM coding endpoint occasionally wedges a request with no error and no
  byte flow — the SDK read timeout never fires (it only guards inter-byte gaps).
  On TRACE-RTL, four sectionwise attempts (10–13) all hung ≥28 min on the same
  first section call with zero checkpoints written; `_compress_to_page_budget`'s
  whole-doc call had the same exposure.
- **Wiki**: this entry; `agent-content-refinement.md` (deadline + thinking notes).
- **Verified**: `ast.parse` + module import OK; A/B probe (thinking on = wedge,
  off = 10.3 s return, `PASS` verdict); production sweeps (attempt 17) completed
  28p → 24p → 21p → 20p with zero wedged-call losses — every timed-out call kept
  its section's original text and the sweep proceeded.
